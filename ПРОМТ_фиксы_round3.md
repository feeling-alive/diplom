# Промт для Claude Code — раунд 3 (правки после демо)

Контекст: проект FinTrack (dashboard-app). FastAPI + PostgreSQL + Redis, React/TS + vite-proxy.
БД работает. Конвенции: verbose-логи, тесты для критичных бэкенд-правок, graceful-degradation,
не ломать рабочее (Google-вход, перевод новостей, drag-and-drop). По фазам, после каждой —
самопроверка и коммит. В конце — отчёт. Ключи — через get_api_key (БД→.env).

=========================================================
ФАЗА A — 🔴 Светлая тема и активы
=========================================================

A1. Убрать тёмную тему во всём приложении — оставить только светлую.
- Удалить переключатель темы и тёмную ветку: в SettingsContext убрать тему dark (или жёстко
  зафиксировать light), снять установку data-theme="dark" на <html>, удалить блок
  html[data-theme="dark"]{...} и тёмные оверрайды в index.css. Опцию темы в настройках убрать.
- Проверить, что нигде не осталось тёмного фона/остатков; приложение всегда светлое.

A2. Вернуть иконки активов в виджете «Тикер активов».
- При прошлой правке раскладки у тикера убрали иконки монет/активов — вернуть их как было,
  сохранив исправленную раскладку (символ с ellipsis, цена не наезжает). Файл MarketTicker.

A3. Убрать несуществующий актив WMT (Walmart).
- Удалить WMT из frontend/src/data/prices.json и из всех списков/маппингов, где он фигурирует
  (обзор рынка, поиск, тикер, скринер). Убедиться, что страница WMT больше не открывается.

A4. Заменить BNB — его нет в наших данных.
- BNB используется в виджете «Корреляции» (и, возможно, ещё где-то), но данных по нему нет
  (в матрице всё 0.00). Заменить BNB на существующий у нас актив из prices.json (например, ADA
  или LINK). Проверить, что в матрице корреляций больше нет пустых столбцов.

=========================================================
ФАЗА B — 🔴 Виджеты, которые не работают
=========================================================

B1. «График цены» (price_chart) — показывает плоский/ненастоящий график (цена при этом верная).
- Строить график из реальных свечей (useOHLCV / тот же источник, что страница актива), а не из
  mock. Убедиться, что форма графика соответствует реальным данным.

B2. «Теханализ» — всегда «Нейтрально».
- Сейчас виджет всегда отдаёт нейтральный вердикт. Считать реальные RSI/MACD/тренд по OHLCV
  выбранного актива (как в features.py) и показывать настоящий вердикт, меняющийся по активу.

B3. «Gas трекер» — не обновляется, висит на статике 24 gwei с пометкой «демо-данные».
- Сейчас RPC-запрос (ethereum-rpc.publicnode.com, eth_gasPrice) не отрабатывает и виджет падает
  на статический фоллбэк. Починить живой источник газа (рабочий публичный RPC или другой
  бесплатный источник), убрать пометку «демо» когда данные живые, обеспечить обновление по TTL.

B4. «Настроение рынка» (Fear & Greed) — всегда 17.
- Значение залипло (стале/фоллбэк). Проверить fng.py: индекс должен реально подтягиваться с
  alternative.me и обновляться по TTL, а не возвращать одно и то же. Если кэш «вечный» — починить TTL.

=========================================================
ФАЗА C — 🔴 ИИ-чат: быстрые действия и инструменты
=========================================================

C1. Добавить реальный инструмент «топ-муверы» и подключить его к ассистенту.
- Сейчас «Растущие активы» возвращают общий ответ с BTC/ETH, а «Падающие активы» не отвечают
  вовсе — потому что у ассистента нет инструмента для топ-движений.
- Backend: добавить эндпоинт и Groq-tool get_top_movers(direction: "up"|"down", limit=5),
  который возвращает РЕАЛЬНЫЕ активы с наибольшим ростом/падением за сегодня по всем классам
  (криптовалюты, акции, валюты), отсортированные по проценту изменения, в виде карточек
  (как search_news/get_asset). Источник — те же котировки, что использует обзор рынка.
- Подключить tool в чат (chat.py _CHAT_TOOLS + runner), чтобы запросы «какие активы растут/падают
  сильнее всего» давали настоящий список карточек. Пример ожидания: на запрос падающих — выдать,
  например, Sonic (упал на ~15%) и другие реально падающие, а не общий текст.

C2. Заменить чип «Индекс страха и жадности» на чип «Что ты умеешь».
- В ChatPage.tsx (массив быстрых блоков) заменить четвёртый чип на «Что ты умеешь» с иконкой;
  по нажатию ассистент кратко объясняет свои возможности, например: «Я — ИИ-ассистент платформы.
  Умею искать свежие новости, находить активы и показывать топ растущих и падающих, а также
  рассказывать о ситуации на рынке. Не даю индивидуальных инвестиционных рекомендаций.»
  (можно отдавать такой ответ напрямую, без обращения к модели, либо системным промптом.)
- Чипсы «Свежие новости» (работает), «Растущие активы» и «Падающие активы» — оставить, но они
  должны работать через новый tool из C1.

=========================================================
ФАЗА D — 🟡 Данные, дашборд, производительность
=========================================================

D1. Почистить все комментарии на сайте.
- Удалить все записи из таблицы comments и связанные comment_reactions (и уведомления типа
  reaction, ссылающиеся на них). Сделать одноразовым безопасным скриптом (как _drop_subscriptions)
  или админ-действием; данные пользователей и новостей не трогать.

D2. Увеличить зону растягивания виджетов.
- Сейчас хит-зона ресайза по краям и углам слишком маленькая, тяжело попасть. Увеличить
  область захвата (например, с ~20px до ~28–32px) у .react-resizable-handle по всем направлениям
  (углы и стороны), не показывая визуальных маркеров — только курсор. Не ломать drag за шапку.

D3. Оптимизировать открытие дашборда.
- Открытие/возврат на дашборд всё ещё подтормаживает при многих виджетах. Снизить шторм запросов:
  кэш TanStack Query (staleTime/keepPreviousData), ограничить параллелизм одновременных fetch,
  ленивая подгрузка тяжёлых виджетов вне вьюпорта, мемоизация. Цель — заметно быстрее открытие.
