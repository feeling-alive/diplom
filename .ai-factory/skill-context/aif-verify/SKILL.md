## Rules

### DnD interactions (react-grid-layout, dnd-kit) require manual browser verification
**Source**: patch 2026-05-17-02.33.md (preventCollision bug was invisible to vitest + jsdom; only surfaced in real browser drag)
**Rule**: jsdom (the DOM used by Vitest in this project) does not simulate the pointerdown → pointermove → pointerup sequence that `react-grid-layout`, `@dnd-kit/core`, and similar libraries depend on. As a result:
- Unit/component tests pass even when drag is silently broken (placement off, drop rejected, neighbours don't shuffle).
- Resize handles, draggable handles, and collision/compaction behaviour are NOT covered by any automated test on this stack.

When verifying a task that touched RGL / dnd-kit / drag interactions:
1. Do NOT mark the task as "done" or "verified" based on `npx vitest run` + `npx tsc --noEmit` alone.
2. The verification report MUST include either:
   - A line item "needs manual browser QA: drag / resize / drop in `npm run dev`" listing the exact interactions to check (e.g., "drag widget A onto widget B → B shifts down; resize widget by SE handle → contents reflow without overflow"), OR
   - The user's confirmation that they have already exercised the interactions in the browser.
3. Files that count as DnD-touching: anything importing from `react-grid-layout*`, `@dnd-kit/*`, or `react-dnd`; CSS files touching `.react-grid-*` / `.react-resizable-*` selectors; components rendering `draggableHandle`, resize handles, or `onDragStart/Stop/Drop` callbacks.
