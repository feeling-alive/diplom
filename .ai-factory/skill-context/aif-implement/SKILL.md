### Framer Motion: use `backgroundColor` not `background` in animation props
**Source**: codebase convention — AssetTable.tsx, AssetStrip.tsx
**Rule**: In Framer Motion `whileHover`, `animate`, and `initial` props, always use `backgroundColor` instead of `background`. The shorthand `background` combined with a `React.CSSProperties` cast triggers TS2590 "union type too complex" in TypeScript strict mode. Framer Motion's `TargetAndTransition` natively accepts `backgroundColor` — no cast is needed.

### lightweight-charts: PricePoint timestamps are milliseconds — convert to seconds
**Source**: codebase convention — src/types/market.types.ts (PricePoint.timestamp), CandlestickChart.tsx

```ts

const candles = data
  .slice()
  .sort((a, b) => a.timestamp - b.timestamp)

    open: p.open,
    high: p.high,
    low: p.low,
    close: p.close,
  }))

```

**Rule**: The Bash tool on Windows runs a POSIX shell where CMD's `del` command is not available. To delete files, use `rm "C:/absolute/path/to/file"` with the full path quoted. Always use forward slashes or fully quoted backslash paths.

### Vite extension conflict: `.jsx` silently shadows `.tsx`

**Rule**: Vite's default extension resolution processes `.jsx` before `.tsx`. If `Foo.jsx` and `Foo.tsx` coexist in the same directory, Vite silently uses `Foo.jsx` and ignores `Foo.tsx`. When replacing a `.jsx` file with a `.tsx` file, delete the `.jsx` immediately — never allow both to coexist.

### react-grid-layout v2: baseline integration kit
**Source**: patches 2026-05-17-02.33.md, 2026-05-17-02.49.md, 2026-05-17-03.48.md (preventCollision, missing min/max, WidthProvider — three sessions, same root cause family)
**Rule**: When integrating `react-grid-layout` v2 in this project, the minimum config that produces working iPhone-style DnD is:
1. **Wrap with `WidthProvider`** from `react-grid-layout/legacy` (NOT main entry — see import-paths rule). Without it, RGL falls back to internal ~1200px width; drag/resize coordinates are computed against phantom geometry and visibly mismatch the container.
2. **Pass `minW/maxW/minH/maxH` on every layout item**, not just in `onResize*` callbacks. Without per-item bounds, RGL allows unbounded resize during drag and only clamps on stop — by then sliders have already shifted neighbours into invalid coordinates.
3. **Use the library's `Layout` (readonly LayoutItem[]) and `LayoutItem` types** for callbacks. If you find yourself stacking `@ts-expect-error` on every RGL callback, your local item type is wrong — fix the type, not the suppression.
4. **Be explicit about `compactType` × `preventCollision` × `isDroppable`.** RGL's defaults (`compactType="vertical"`, `preventCollision={false}`) are tuned for iPhone-style push-and-compact. `preventCollision={true}` REJECTS any move that would overlap a neighbour — drag silently reverts; if you ever set `true`, also remove neighbour-shuffle animations (they will never fire).
Skeleton:
```tsx
import GridLayout, { WidthProvider, type Layout, type LayoutItem } from 'react-grid-layout/legacy'
const ResponsiveGrid = WidthProvider(GridLayout)
// layout: each item has i, x, y, w, h + minW/maxW/minH/maxH from registry
<ResponsiveGrid layout={layout} cols={4} rowHeight={160}
  compactType="vertical" preventCollision={false}
  isDraggable={true} isResizable={true}
  draggableHandle=".widget-drag-handle"
  onLayoutChange={(l: Layout) => ...} ... />
```

### react-grid-layout v2: import `WidthProvider`/`Layout`/`LayoutItem` from `/legacy`
**Source**: patch 2026-05-17-03.48.md (TS2614 'no exported member WidthProvider' from main entry)
**Rule**: In `react-grid-layout` v2.x the main entry (`react-grid-layout`) no longer re-exports `WidthProvider`, `Responsive`, `Layout`, or `LayoutItem` — they live in the `/legacy` subpath. Import like this:

If you import them from `react-grid-layout` directly, TS will error with TS2614 and runtime will be `undefined`. Vitest mocks must also target `react-grid-layout/legacy` and supply a pass-through `WidthProvider`:
```ts
vi.mock('react-grid-layout/legacy', () => ({

```

### react-grid-layout: axis-lock idiom via min===max
**Source**: patch 2026-05-17-03.06.md (per-widget resize axes redesign in WIDGET_REGISTRY)
**Rule**: To lock the resize axis of an item in react-grid-layout, set `minW === maxW` (height-only resize) or `minH === maxH` (width-only resize). RGL natively hides the corresponding resize handle and ignores drag on the locked axis — no custom CSS, no `onResize` interception needed. Use this for any item with a fixed-shape design constraint (single-row KPI banners → `minH===maxH===1`, vertical lists → `minW===maxW`).

### react-grid-layout: no hand-rolled pagination by widget `y`
**Source**: patch 2026-05-17-03.48.md (bottom-dead-zone bug from `pageBoundary=4` splitting)
**Rule**: Do not split RGL widgets into "pages" by their `y` coordinate. With `compactType="vertical"` and `preventCollision={false}`, RGL freely shifts items across rows during compaction — any widget pushed past your `pageBoundary` row silently leaves the current page and appears to vanish. If pagination is genuinely required, base it on an explicit user-controlled `pageId` field stored on each widget, not on a coordinate. Default: skip pagination, use one continuous vertical-scroll surface (`flex: 1; overflow-y: auto`).

### Recharts ResponsiveContainer: parent must have explicit height
**Source**: patch 2026-05-17-02.49.md (WidgetPreview previews rendered empty/0-px)
**Rule**: `<ResponsiveContainer width="100%" height="100%">` reads its height from the DOM parent via ResizeObserver. If the parent has `height: auto`, `height: fit-content`, or is sized by its children, the container collapses to 0 px and the chart disappears. Two acceptable parent shapes:
- **Adaptive cells (grid items, flex children):** parent is `flex: 1; min-height: 0` inside a `display: flex; flex-direction: column` ancestor. The `min-height: 0` is mandatory — without it, flex children refuse to shrink below their content.
- **Static previews (modals, picker cards, docs):** parent has explicit `height: Npx` (or use a `PREVIEW_HEIGHTS` map keyed by widget type).
Never wrap ResponsiveContainer in a plain `<div style={{ height: '100%' }}>` whose grandparent doesn't enforce one of the two shapes above.

### localStorage persisted state: version key + load-time clamp + UI reset
**Source**: patches 2026-05-17-02.49.md, 2026-05-17-03.06.md (stale localStorage feeding stale layouts after registry refactor)
**Rule**: Any persisted UI state (localStorage, sessionStorage, IndexedDB) needs three guards in this project. Missing any one of them produces the recurring "I deleted the key but it came back" / "old size still shows up" bug.
1. **Versioned key.** Use `<feature>_<v>` (e.g., `fintrack_widgets_v3`). When the persisted schema changes (new fields, new bounds, removed properties), bump the version AND keep a `LEGACY_STORAGE_KEYS` array; on every load, `removeItem` each legacy key before reading the current one. Log it: `console.debug('[FIX] purging legacy localStorage key %s', k)`.
2. **Load-time clamp/validate.** Never trust raw JSON from storage. After `JSON.parse`, walk every entry and clamp values against the current schema/registry. For widget layouts: clamp `w` to `[minW, maxW]` and `h` to `[minH, maxH]`. Log clamping events so DevTools shows when the self-heal fired.
3. **UI reset escape hatch.** Provide a visible "Reset to defaults" button (e.g., RotateCcw icon in header) wired to `confirm()` + replace state with `createDefaults()`. Users without DevTools must have a one-click way out of a stuck state.

### Widget registry consistency: availableSizes ⊂ bounds + real size in previews
**Source**: patches 2026-05-17-02.49.md, 2026-05-17-03.06.md (preset/bound mismatch + previews rendering wrong shape)
**Rule**: When a widget registry has both `availableSizes: WidgetSize[]` (UI preset list) and `minW/maxW/minH/maxH` (physical bounds), the two MUST agree:
- Every preset `(w, h)` satisfies `minW ≤ w ≤ maxW` AND `minH ≤ h ≤ maxH`. A preset outside bounds is a registry bug — it shows the user an option they can't actually keep.
- Every bound has at least one corresponding preset. A bound with no preset suggests the bound is wrong (too permissive).
- When rendering adaptive widgets in previews/pickers, pass the user's **currently selected size** (`selected.w`, `selected.h`) to the preview component, not a default 2×2. Otherwise the preview shows one shape and the live widget renders a different shape.
Treat any divergence as a registry-level fix; do not patch around it in components.
