### Framer Motion: use `backgroundColor` not `background` in animation props
**Source**: codebase convention — AssetTable.tsx, AssetStrip.tsx
**Rule**: In Framer Motion `whileHover`, `animate`, and `initial` props, always use `backgroundColor` instead of `background`. The shorthand `background` combined with a `React.CSSProperties` cast triggers TS2590 "union type too complex" in TypeScript strict mode. Framer Motion's `TargetAndTransition` natively accepts `backgroundColor` — no cast is needed.

### Test isolation: components using `useNavigate` require Router context
**Source**: codebase bug — AssetTable.test.tsx, MarketOverview.test.tsx
**Rule**: When a component calls `useNavigate`, tests must provide a Router context or the hook will throw "useNavigate() may be used only in the context of a <Router>". Apply one of:
- If `vi.mock('react-router-dom', ...)` already exists: add `useNavigate: () => () => undefined` to the mock object.
- If no mock exists: wrap every `render(...)` call in `<MemoryRouter>` from react-router-dom.
Never write a test for a component that uses `useNavigate` without one of these two fixes.

### Test assertions: use `getByRole('heading')` when title text matches a NavLink label
**Source**: codebase bug — MarketOverview.test.tsx
**Rule**: FinTrackNavBar renders on every page in the app-page shell. If a page `<h1>` shares its text with a NavLink label (e.g., "Обзор рынка"), `screen.getByText('...')` finds 2+ elements and throws. Always use `screen.getByRole('heading', { name: '...' })` to assert a page's main `<h1>` heading.

### Test assertions: use `getAllByText` for text that appears in multiple sections
**Source**: codebase bug — MarketOverview.test.tsx
**Rule**: Labels like "Объём 24ч" appear in both MarketSummaryBar stat cards and the AssetTable column header. Asset symbols appear in both TopMovers and AssetTable rows. When asserting text that may render in multiple sibling components, use `screen.getAllByText('...').length >= N` instead of `screen.getByText('...')`. Minimum N is typically 1.

### lightweight-charts: PricePoint timestamps are milliseconds — convert to seconds
**Source**: codebase convention — src/types/market.types.ts (PricePoint.timestamp), CandlestickChart.tsx
**Rule**: `PricePoint.timestamp` stores Unix milliseconds. lightweight-charts `Time` expects Unix seconds. Always convert and sort before `setData()`:
```ts
import type { Time } from 'lightweight-charts'
const candles = data
  .slice()
  .sort((a, b) => a.timestamp - b.timestamp)
  .map(p => ({
    time: Math.floor(p.timestamp / 1000) as Time,
    open: p.open,
    high: p.high,
    low: p.low,
    close: p.close,
  }))
series.setData(candles)
```

### react-router-dom NavLink: `end` prop required on root path
**Source**: codebase convention — FinTrackNavBar.tsx
**Rule**: Any `<NavLink to="/">` must include the `end` prop. Without it, the root NavLink uses prefix matching and remains `isActive` on every route in the application. This is already enforced in FinTrackNavBar — maintain it when adding new NavLinks.

### Windows Bash tool: use `rm` not `del` for file deletion
**Source**: codebase bug — session shell error on Windows
**Rule**: The Bash tool on Windows runs a POSIX shell where CMD's `del` command is not available. To delete files, use `rm "C:/absolute/path/to/file"` with the full path quoted. Always use forward slashes or fully quoted backslash paths.

### Vite extension conflict: `.jsx` silently shadows `.tsx`
**Source**: codebase bug — App.jsx + App.tsx coexistence
**Rule**: Vite's default extension resolution processes `.jsx` before `.tsx`. If `Foo.jsx` and `Foo.tsx` coexist in the same directory, Vite silently uses `Foo.jsx` and ignores `Foo.tsx`. When replacing a `.jsx` file with a `.tsx` file, delete the `.jsx` immediately — never allow both to coexist.
