# Storage версия + per-widget resize оси (только ширина / только высота / обе)

**Date:** 2026-05-17 03:06
**Files:** src/constants/widgets.registry.ts, src/pages/Dashboard.tsx, src/components/dashboard/DashboardHeader.tsx
**Severity:** medium

## Problem

После прошлых фиксов (`preventCollision=false`, clamp при загрузке, мин/макс в layout items) две вещи продолжали раздражать пользователя:

1. **Ключ `fintrack_widgets_v2` возвращался** в localStorage даже после ручного удаления через DevTools. После refresh Dashboard сам пересоздавал дефолтный layout и записывал его обратно — пользователь не видел разницы.
2. **Resize-оси были одинаковые для всех виджетов.** Пользователю не хватало семантики: «KPI — это полоса, она должна тянуться только вширь», «вотчлист — это вертикальный список, только в высоту», «график — обе оси». Сейчас registry разрешал большинству виджетов изменяться по обеим осям без ограничений, и пользователь промахивался по ожидаемому поведению.

## Root Cause

**1. Persisted state outlives schema refactors.**
`STORAGE_KEY` оставался `fintrack_widgets_v2` после того как: (а) поменялся registry с `maxH`, (б) поменялся `preventCollision`, (в) поменялась логика clamp. Удаление ключа руками — это полу-решение: оно работает один раз, но любой пользователь без DevTools-навыков застрянет. Дефолты пересоздаются → проблема возвращается до тех пор пока пользователь сам не подвинет всё руками.

**2. `availableSizes` ≠ `minW/maxW/minH/maxH`.**
В предыдущей версии registry эти два поля были несогласованы. Например, у `news` было `availableSizes: [2×2, 3×2]` (только две опции), но `minW:2, maxW:3, minH:2, maxH:4` — то есть пользователь технически мог поресайзить до 3×4 (вне списка). Семантика "ось resize" вообще нигде не была выражена явно — `minW===maxW` как способ заблокировать ось не использовался.

## Solution

**1. Bump `STORAGE_KEY` → `fintrack_widgets_v3` + purge legacy keys.**

В `Dashboard.tsx`:
- `STORAGE_KEY = 'fintrack_widgets_v3'`
- `LEGACY_STORAGE_KEYS = ['fintrack_widgets_v2', 'fintrack_widgets']`
- `loadWidgets()` в самом начале проходится по legacy ключам и `localStorage.removeItem` для каждого, с логом `[FIX] purging legacy localStorage key %s`.

Все клиенты при следующем заходе получают чистый дефолтный layout, и старые залётевшие данные больше не маячат в DevTools.

**2. Кнопка «Сбросить раскладку» в `DashboardHeader`.**

Иконка `RotateCcw` появляется анимировано только в режиме редактирования (`AnimatePresence`). При клике — `window.confirm('Сбросить раскладку дашборда к стандартной?')` → `handleResetLayout` в `Dashboard.tsx` вызывает `createDefaultWidgets()` и пишет в storage. Пользователь больше не зависит от DevTools.

**3. Семантика осей в `WIDGET_REGISTRY` через `minW === maxW` и `minH === maxH`.**

Перепроектировал каждый виджет:

| Тип | Ось resize | Лимиты |
|---|---|---|
| `kpi_portfolio` | только ширина | minH=maxH=1, w 2-4 |
| `market_volume` | только ширина | minH=maxH=1, w 2-4 |
| `watchlist` | только высота | minW=maxW=2, h 2-4 |
| `price_chart` | обе | w 2-4, h 2-4 |
| `allocation` | обе | w 1-3, h 2-4 |
| `community` | обе | w 2-3, h 2-4 |
| `news` | обе | w 2-3, h 2-4 |
| `top_movers` | обе | w 2-4, h 2-4 |
| `forex_rates` | обе | w 2-4, h 1-3 |
| `fear_greed` | обе | w 1-2, h 1-2 |
| `trending_coins` | обе | w 2-3, h 2-4 |

Где `min === max` для оси, RGL нативно скрывает соответствующий resize-handle (так как тянуть некуда). Пользователь сразу видит: KPI можно тянуть только за правый край, watchlist — только за нижний.

`availableSizes` синхронизированы с лимитами — никакая опция не выходит за `min/max`.

## Prevention

- **Bump storage key version вместе с изменением схемы persisted state.** Это основной механизм миграции frontend localStorage без backend-миграций. Дёшево, безопасно, работает у всех пользователей одновременно. Документация эталонного frontend storage может включать "если меняешь shape — bump key" как hard rule.
- **`minW === maxW` / `minH === maxH` — это идиоматический способ заблокировать ось resize в react-grid-layout.** Не нужен ни кастомный CSS, ни перехват onResize. RGL сам скрывает handle и не реагирует на drag по заблокированной оси.
- **Не оставлять пользователя без UI-эскейпа.** Если storage-state может застрять в плохом состоянии (любой persisted state может), всегда давай кнопку «Сбросить» рядом — это снимает нагрузку и с пользователя, и с support. В edit mode это органично смотрится.
- **`availableSizes` (UI-список пресетов) и `minW/maxW/minH/maxH` (физические границы) не должны конфликтовать.** Любая пресет-опция должна быть внутри границ; любая граница должна иметь хотя бы один пресет. Если они разъехались — это код-смелл, register нуждается в правке.
